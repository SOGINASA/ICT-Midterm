# Локальный backend TengeFlow

Собственный Flask API хранит аккаунты и расходы через SQLAlchemy в SQLite. Миграции выполняет Alembic/Flask-Migrate. Backend не использует Supabase, Docker или базы других проектов.

## Запуск и адреса

Требуются Node.js 22 и Python 3.11+. Из корня проекта:

```sh
npm install
npm run backend:start
npm start
```

Первый запуск создаёт `backend/.venv`, устанавливает зависимости и применяет миграции. Последующие запуски сохраняют данные и применяют новые миграции. API слушает только локальный адрес `127.0.0.1:8000`.

| Сервис | Адрес |
| --- | --- |
| Frontend | http://localhost:3000 |
| API | http://127.0.0.1:8000/api |
| Локальные письма | http://127.0.0.1:8000/api/dev/inbox |

Frontend использует `REACT_APP_API_URL=/api`; прокси CRA передаёт эти запросы локальному API. После изменения окружения перезапустите `npm start`. Используйте один адрес frontend на протяжении сценария, чтобы cookie и ссылки относились к одному сайту.

## Регистрация и настройка

1. Зарегистрируйтесь с тестовым email и паролем от восьми символов.
2. Откройте локальный inbox и ссылку подтверждения из своего письма. В режиме разработки реальные письма не отправляются.
3. Укажите имя, месячный бюджет и лимиты пяти категорий. Можно оставить часть бюджета нераспределённой.
4. Добавьте расход, обновите страницу, выйдите и войдите снова. Данные должны сохраниться; повторная настройка не нужна.
5. Для восстановления пароля используйте **Forgot password**. Ссылка также появится в локальном inbox.

Ссылки одноразовые и имеют срок действия. Новый аккаунт не содержит демонстрационных расходов. Черновик настройки сохраняется в рамках браузерного сеанса, но завершённой настройка считается только после подтверждения сервера.

## Остановка и данные

```sh
npm run backend:status
npm run backend:stop
npm run backend:start
```

База находится в `backend/instance/tengeflow.sqlite3`. Обычная остановка её не удаляет. Не удаляйте файл базы или каталог `instance`, если хотите сохранить аккаунты. Для резервной копии остановите backend и скопируйте файл базы в защищённое место; затем запустите сервер снова.

Для ручного запуска, когда окружение уже создано:

```sh
cd backend
.venv/bin/flask --app app db upgrade
.venv/bin/python app.py
```

Не запускайте ручной сервер одновременно с `backend:start` на том же порту.

## Проверки

Из корня проекта:

```sh
npm run backend:test
npm run typecheck
npm run test:ci
RUN_ACCOUNT_E2E=1 npm run test:e2e -- e2e/account.spec.js
```

`backend:test` запускает pytest в Python-окружении backend; тесты используют отдельную тестовую базу. Браузерным сценариям аккаунта нужны работающие локальные API и frontend; они создают собственные тестовые аккаунты. Локальный inbox предназначен только для разработки и недоступен в production.

Для опубликованного сайта нужен отдельный Python-хостинг. Настройка постоянной базы, SMTP и прокси Vercel описана в [BACKEND_SETUP.md](BACKEND_SETUP.md).
