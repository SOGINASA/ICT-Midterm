# TengeFlow

Трекер расходов в тенге для ICT Midterm: иллюстрированная главная, регистрация, настройка нового аккаунта и личный кабинет с мобильной адаптацией.

**Frontend:** Create React App, React, TypeScript, Tailwind и Zustand. **Backend:** собственный Flask API, SQLAlchemy и Alembic, по принципу проектов `sqo_cs2` и `erik`. Локально используется SQLite; для опубликованной версии предусмотрен PostgreSQL. Supabase больше не используется.

## Запуск

Требуются Node.js 22 (`.nvmrc`) и Python 3.11+. Из корня проекта:

```sh
npm install
npm run backend:start
npm start
```

Команда `backend:start` создаёт Python-окружение, устанавливает зависимости, применяет миграции и запускает API. Docker и внешний почтовый сервис для локальной разработки не нужны.

- Приложение: http://localhost:3000
- Backend: http://127.0.0.1:8000
- Локальные письма: http://127.0.0.1:8000/api/dev/inbox

После регистрации откройте письмо подтверждения в локальном inbox. Новый аккаунт проходит три шага: имя, месячный бюджет и лимиты категорий. Затем открывается кабинет с пустой историей расходов. Письма локального режима остаются на компьютере.

```sh
npm run backend:status
npm run backend:stop
```

Остановка сохраняет базу `backend/instance/tengeflow.sqlite3`. Повторный запуск — `npm run backend:start`. Подробности — [локальный backend](docs/LOCAL_BACKEND.md).

Для демонстрации без сервера запустите только `npm start` и выберите **Try demo** на главной. Демо хранит собственные данные в браузере.

## Проверки

```sh
npm run typecheck
npm run test:ci
npm run backend:test
npm run test:e2e
RUN_ACCOUNT_E2E=1 npm run test:e2e -- e2e/account.spec.js
npm run build
```

Playwright использует Google Chrome и запускает frontend, если он ещё не работает. При отсутствии браузера: `npx playwright install chrome`. Для сценариев реального аккаунта нужен локальный backend; тесты используют отдельные временные аккаунты. Набор проверяет регистрацию через письмо, настройку, расходы, повторный вход, восстановление пароля и изоляцию пользователей. Production-сборка создаётся в `build/`.

## Страницы

| Экран | Адрес | Возможности |
| --- | --- | --- |
| Главная | `/` | О проекте, иллюстрации, интерактивное превью |
| Вход и регистрация | `/login`, `/register` | Email, пароль, подтверждение адреса |
| Восстановление | `/forgot-password`, `/reset-password` | Письмо и новый пароль |
| Подтверждение | `/auth/callback` | Обработка ссылки из письма |
| Настройка | `/onboarding` | Имя, месячный бюджет, пять лимитов |
| Демо | `/demo` | Отдельный локальный режим |
| Обзор | `/app` | Бюджет, расходы, остаток, последние покупки |
| Добавление | `/app/add` | Сумма, категория, способ оплаты, дата, заметка |
| История | `/app/transactions` | Поиск, фильтры, редактирование, удаление |
| Бюджеты | `/app/budgets` | Общий бюджет и лимиты категорий |
| Аналитика | `/app/insights` | Распределение и динамика расходов |

Незавершённый новый аккаунт направляется в настройку даже по прямой ссылке на кабинет. После сохранения повторный вход сразу открывает `/app`. Демо пропускает настройку. Мобильная версия включает нижнюю навигацию, safe-area отступы и адаптивные формы; manifest и иконки позволяют добавить сайт на домашний экран. Service worker пока отсутствует.

## Данные и архитектура

```text
React → отдельный Zustand store → FinanceRepository
                                  ├─ демо → localStorage
                                  └─ аккаунт → Flask API → SQLAlchemy → база
Авторизация → сессия → профиль → настройка или кабинет
```

| | Демо | Личный аккаунт |
| --- | --- | --- |
| Начальные данные | Бюджет ₸120 000, расходы ₸77 650 | Пустая история; бюджет выбирается при настройке |
| Хранение | `localStorage` | SQLite локально, PostgreSQL на сервере |
| Без сети | Локальное сохранение, имитация очереди | Для загрузки и сохранения нужна сеть |
| Черновик расхода | `localStorage` | Отдельный ключ пользователя в `sessionStorage` |
| Авторизация | Не требуется | Короткий access token в памяти, refresh cookie `HttpOnly` |

Данные демо не отправляются в аккаунт. Для каждой личности создаётся отдельный store; финансовый снимок аккаунта не сохраняется в `localStorage`. API определяет владельца из проверенной сессии и ограничивает все операции его записями. Настройка сохраняется одной транзакцией; повторный запрос не сбрасывает уже завершённый результат.

Подробности — [архитектура backend](docs/BACKEND_INTEGRATION.md). Оригиналы иллюстраций и промпты — [design/landing/ASSETS.md](design/landing/ASSETS.md).

## Публикация

Frontend можно разместить на Vercel: Build Command `npm run build`, Output Directory `build`. Для работающих аккаунтов нужен отдельно размещённый Python backend с постоянной базой и SMTP. Локальный сервер компьютера посетителям сайта недоступен. Внешний deployment пока не выполнен.

Браузер обращается к `/api`: локально запросы перенаправляет CRA, на Vercel — внешний rewrite. Настройте адрес размещённого backend перед публикацией:

```sh
npm run deploy:api -- https://your-backend.example
```

В frontend используется только `REACT_APP_API_URL=/api`; пароли базы, SMTP и ключ JWT остаются на backend. Полный порядок миграций, переменные и Gunicorn — [BACKEND_SETUP.md](docs/BACKEND_SETUP.md).
